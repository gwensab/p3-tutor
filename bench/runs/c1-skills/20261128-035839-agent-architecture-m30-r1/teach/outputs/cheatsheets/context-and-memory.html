Context and memory

From lesson 1.

The window

  • Holds: system prompt, tool definitions, messages, tool results, and the reply.
  • Rough size: 1 token ≈ 4 English characters.
  • The model keeps nothing between calls; the history is sent (and billed) again.
  • Window use = size of one call. Billed input = sum over all calls.
  • Input cost = total input tokens ÷ 1,000,000 × price per million.
  • More text can reduce accurate recall (context rot).

Where should this information live?

If it is...Then...
Needed for the next decisionKeep it in context
A used, bulky tool resultReplace with a short stub
A long historyCompact: summarize and restart (details can be lost)
Useful next visit, no official sourceSave a note; load it later
Changing or safety-criticalLook up the official record now
A small part of a large documentRetrieve the matching chunks

Memory

  • Short-term: one conversation's history. Long-term: stored across sessions.
  • Profile: one updated record. Collection: many notes, searched.
  • Write during the chat (available now, may add delay) or in the background (no delay, may lag).

Retrieval

  • Prepare: split into chunks, label each with its source, index.
  • Query: search, add the top chunks to context.
  • Embeddings match meaning; keyword search (BM25) matches exact codes and names.
